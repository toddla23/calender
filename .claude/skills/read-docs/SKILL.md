# docs 읽기

1. `docs/` 아래 `.md` 파일을 번호 순서대로 **전부** Read 로 읽는다. 이미 세션 시작 때 들어온 01·05·06 도 바뀌었을 수 있으니 다시 읽는다.
   - 01-overview: 무엇을 만드는지, 원칙
   - 02-architecture: 구조, 스택, DB, 보안, 측정값
   - 03-protocol: 인증, 동기화 API, 제한값
   - 04-features: 기능 명세 (목표 / 선행 / 범위 / 완료 조건 / 사용자 확인 방법)
   - 05-progress: 상태 표, 작업 로그
   - 06-decisions: 결정 D-0xx, 열린 질문 O-0x
   - 07-release: 빌드·테스트·릴리스
   - 08-hosting: 파이 서버 운영, 백업·복원
2. 읽은 뒤 사용자에게 몇 줄로 알린다: 진행중·확인대기인 기능, 다음 `대기` 기능, 아직 열린 질문.
3. `$ARGUMENTS` 가 있으면 그 주제와 관련된 문서 절을 짚어 답한다.

# 문서 규칙 (작업하는 동안 지킨다)

- 기능을 시작하면 05-progress 상태를 `진행중`, 확인 요청할 때 `확인대기`. `완료`는 **사용자가 승인한 뒤에만**.
- 작업 로그는 05-progress "작업 로그" 맨 위에 `YYYY-MM-DD F00 — 한 줄`.
- 새 기능은 04-features 형식(목표 / 선행 / 범위 / 범위 밖 / 완료 조건 / 사용자 확인 방법)으로 먼저 적고 05 표에 `대기`로 넣는다.
- 결정은 06-decisions 에 D-0xx 로 이유와 함께. 뒤집으려면 사용자와 합의 → 새 항목 + 이전 항목에 `→ D-0xx로 대체`. 착수 전에 물어야 할 것은 O-0x.
- 코드를 바꾸면 관련 문서(02·03·07·08)도 같은 커밋에서 고친다. README 에는 기능 설명만 둔다.
