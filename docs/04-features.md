# 04. 기능 명세

각 기능은 **사용자가 직접 실행해서 확인할 수 있는 단위**로 나눴다. 형식:

- **목표**: 이 기능이 끝나면 무엇이 되는가
- **선행**: 먼저 `완료`여야 하는 기능
- **범위 / 범위 밖**: 만들 것과 이번에 만들지 않을 것
- **완료 조건**: 전부 충족해야 `확인대기`로 올릴 수 있다
- **사용자 확인 방법**: 사용자가 실제로 해볼 절차와 기대 결과. 구현 중 명령어가 바뀌면 이 절을 고치고 보고에 반영한다

공통 완료 조건(모든 기능): `npm test` 통과, 관련 문서 갱신, `05-progress.md` 갱신.

F01~F15는 2026-11-14 재구현(커밋 `ca5ba6d`) 이후 README에 있던 내용을 이 형식으로 옮긴 것이다.

## F02. Google 로그인과 허용 목록

- **목표**: 허용 목록에 있는 Google 계정만 들어온다.

- **범위**: OAuth(state + 브라우저 바인딩 쿠키 + PKCE), `ALLOWED_EMAILS`, 세션 쿠키, 기기 토큰, 로그인 실패 IP별 잠금 (03-protocol 1절)
- **범위 밖**: 비밀번호 로그인 (D-002)
- **사용자 확인 방법**
  1. `curl -s -o /dev/null -w '%{http_code}\n' https://raspberry-pi.tailb6b7a3.ts.net/api/me` → `401`
  2. 브라우저로 주소를 열고 `Google 계정으로 로그인` → 달력이 나옴
  3. 목록에 없는 계정으로 로그인 → 들어가지 못함

## F04. 실시간 동기화와 충돌 병합

- **목표**: 한 기기에서 고친 것이 다른 기기에 1초 안에 보이고, 동시에 고쳐도 잃지 않는다.
- **선행**: F03
- **범위**: push/pull/WebSocket, `seq`, `sync_lock`, `applied_ops`, 충돌 병합 (03-protocol 2절)
- **완료 조건**
  - [x] 실시간 반영 1초 이내 (브라우저 두 개 사이 18~170ms)
  - [x] 서버 테스트(인증·동기화·충돌) 통과
- **사용자 확인 방법**
  1. 브라우저 두 개로 같은 칸을 보고 한쪽에서 고침 → 다른 쪽에 바로 보임
  2. 한쪽을 오프라인으로 두고 두 쪽에서 같은 칸을 고친 뒤 연결 → `--- 다른 기기에서 수정 ---`로 합쳐지고 충돌 표시
